    Раздел 0

    Как устроен конвейер

    Шесть приложений передают друг другу работу по цепочке. Настраивать их нужно в порядке этой цепочки: Radarr бесполезен без индексаторов Prowlarr, Prowlarr нечего отдавать без клиента загрузки, а Seerr не с чем связываться, пока не готово всё остальное.

    ПриложениеРоль в конвейереНастраивать
    qBittorrentкачает и раздаётпервым — от него зависят все
    FlareSolverrобходит защиту Cloudflare для индексатороввторым, проверить и забыть
    Prowlarrединый список трекеров, раздаёт его остальнымтретьим
    Radarrрешает что качать, следит за качеством, импортируетчетвёртым
    Jellyfinотдаёт библиотеку на устройствапятым
    Seerrвитрина запросов поверх Radarr и Jellyfinпоследним
    Три способа обратиться к одному и тому же сервису.

    Изнутри сети Docker media — по имени контейнера: http://radarr:7878. Так приложения находят друг друга, и так нужно писать адреса в их настройках.

    Из Home Assistant — по 127.0.0.1:7878: он работает в сети хоста, где опубликованы все порты.

    Из браузера — по 192.168.3.53:7878. Путаница между этими тремя формами и есть самая частая причина «Test failed» при настройке.

    Раздел 1

    Папки и хардлинки

    Самый важный раздел, и единственный, который тяжело переделать потом. Если структуру папок сделать неправильно, всё будет работать — просто каждый фильм займёт на диске вдвое больше места, а импорт будет длиться минутами вместо мгновения.

    1. 1.1 Создать структуру

      sudo mkdir -p /volume1/data/torrents/movies
sudo mkdir -p /volume1/data/torrents/incomplete
sudo mkdir -p /volume1/data/media/movies

# Те же PUID:PGID, что у контейнеров в compose.yaml
sudo chown -R 1026:100 /volume1/data
sudo chmod -R 775 /volume1/data

      Если позже добавите сериалы и Sonarr — по той же схеме появятся torrents/tv и media/tv. Схема расширяется, не ломаясь.

    2. 1.2 Понять, почему монтирование именно такоесуть

      В compose.yaml и qBittorrent, и Radarr получают один и тот же том целиком: 

      volumes:
  - /volume1/data:/data

      Внутри обоих контейнеров пути выглядят одинаково — /data/torrents/… и /data/media/…, — и это одна файловая система. Только при таком условии Radarr может создать хардлинк: вторую ссылку на те же данные вместо копии.

      Как выглядит распространённая ошибка. Смонтировать /volume1/data/torrents:/downloads и /volume1/data/media:/movies двумя отдельными строками. Внутри контейнера это выглядит как две разные файловые системы, хардлинк невозможен, и Radarr честно копирует файл. Внешне всё работает — просто диск кончается вдвое быстрее, а импорт фильма на 20 ГБ занимает пару минут вместо доли секунды.

    3. 1.3 Убедиться, что хардлинки работают

      Проверка занимает двадцать секунд и снимает все сомнения:

      sudo touch /volume1/data/torrents/hardlink.test
sudo ln /volume1/data/torrents/hardlink.test /volume1/data/media/hardlink.test
ls -li /volume1/data/torrents/hardlink.test /volume1/data/media/hardlink.test

      В первой колонке — номер inode. Если числа совпадают, хардлинк создан и всё настроено верно. Во второй колонке будет 2 — столько ссылок теперь у этих данных. 

      sudo rm /volume1/data/torrents/hardlink.test /volume1/data/media/hardlink.test
      Что это значит на практике. Пока существует хотя бы одна ссылка, данные лежат на диске. Поэтому фильм, одновременно раздающийся из torrents и видимый в библиотеке media, занимает место один раз. Раздавать после импорта ничего не стоит — и это меняет отношение к настройке лимитов раздачи в шаге 2.6.
    Раздел 2

    qBittorrent

    Веб-интерфейс на 192.168.3.53:9080. Настраиваем первым: на него будут ссылаться и Prowlarr, и Radarr.

    1. 2.1 Найти временный пароль и сменить егосразу

      Современные версии qBittorrent не имеют пароля по умолчанию: при первом запуске генерируется случайный и печатается в лог контейнера. 

      sudo docker logs qbittorrent 2>&1 | grep -i -B2 -A2 "temporary password"

      Логин — admin, пароль из вывода. Сразу после входа: Настройки → Веб-интерфейс → Аутентификация, задать своё имя пользователя и пароль, сохранить.

      Строки в логе нет? Это баг конкретной версии 4.6.1, где пароль генерировался, но не печатался. Обновите образ — sudo docker compose pull && sudo docker compose up -d в каталоге media — и посмотрите лог заново.

    2. 2.2 Включить VueTorrent

      В compose.yaml уже подключён мод vuetorrent-lsio-mod — современный интерфейс вместо стандартного. Осталось его включить:

      Настройки → Веб-интерфейс → Использовать альтернативный веб-интерфейс → включить, в поле пути указать: 

      /vuetorrent

      Сохранить и обновить страницу.

      Если после сохранения интерфейс не открывается — путь указан неверно и qBittorrent отдаёт пустую страницу. Лечится правкой конфига без интерфейса: sudo docker exec -it qbittorrent sed -i '/AlternativeUIEnabled/d' /config/qBittorrent/qBittorrent.conf, затем перезапуск контейнера.

    3. 2.3 Задать пути загрузок

      Настройки → Загрузки:

      ПараметрЗначение
      Путь сохранения по умолчанию/data/torrents
      Хранить незавершённые торренты ввключить, /data/torrents/incomplete
      Режим управления торрентами по умолчаниюАвтоматический
      При смене категории торрентаПереместить торрент
      Добавлять расширение .!qB к незавершённымвключить
      Автоматический режим означает, что путь сохранения определяется категорией, а не запоминается для каждого торрента отдельно. Именно на это опирается Radarr: он передаёт категорию, и файл сам оказывается в нужной папке.

    4. 2.4 Создать категорию movies

      В боковой панели, правой кнопкой по «Категории» → Добавить категорию:

      Имяmovies
      Путь сохранения/data/torrents/movies

      Ровно это имя мы укажем в Radarr на шаге 5.4. Regex, пробелы и заглавные буквы не нужны — Radarr сравнивает строку буквально.

    5. 2.5 Ограничить число соединенийважно для сети

      Настройки → Соединение:

      ПараметрЗначение
      Порт входящих соединений6881 — совпадает с проброшенным в compose
      Глобальное максимальное число соединений150
      Максимум соединений на торрент40
      Глобальное число слотов отдачи8
      Почему это не придирка. Ваш Keenetic держит таблицу отслеживания соединений на 32 768 записей. Торрент-клиент без ограничений легко открывает несколько тысяч соединений одновременно, а каждое живёт в этой таблице ещё какое-то время после закрытия. Переполнение таблицы выглядит не как «медленный торрент», а как «интернет в доме залип» — у всех сразу, включая телевизор и телефон. Полторы сотни соединений забирают несколько процентов таблицы и оставляют запас остальным.
      Для приватных трекеров в том же разделе отключите DHT, PEX и Local Peer Discovery: правила большинства приватных трекеров это требуют, а пользы от них там нет.

    6. 2.6 Настроить раздачу

      Настройки → BitTorrent → Лимиты раздачи: включить «При достижении рейтинга» — например, 2.0 — и действие Приостановить торрент.

      Приостановить, а не удалить. Благодаря хардлинкам из раздела 1 раздающийся торрент и фильм в библиотеке — это одни и те же данные на диске. Удаление торрента вместе с файлами не освободит места, пока существует вторая ссылка из библиотеки, зато оборвёт раздачу. Единственное, что даёт удаление, — более короткий список в интерфейсе; цена — испорченный рейтинг на приватных трекерах.
      Про входящие соединения. Если весь трафик NAS идёт через VPN-туннель без проброса портов, до вас не достучится никто извне: раздача идёт только тем пирам, к которым qBittorrent подключился сам. Клиент при этом исправен — просто рейтинг растёт медленнее. Если у провайдера туннеля есть port forwarding, пробросьте на нём 6881.
    Раздел 3

    FlareSolverr

    Самый простой из шести: у него нет интерфейса и нет настроек. Внутри — headless-браузер, который проходит проверку Cloudflare вместо Prowlarr.

    1. 3.1 Проверить, что отвечает

      curl -s http://127.0.0.1:8191/ | python3 -m json.tool

      Ожидаемый ответ содержит "msg": "FlareSolverr is ready!" и версию. Адрес для Prowlarr запомните в другой форме — http://flaresolverr:8191, по имени контейнера.

    2. 3.2 Решить, нужен ли он вообще

      FlareSolverr требуется только тем индексаторам, которые прячутся за проверкой Cloudflare. Если все ваши трекеры приватные и такой защиты не имеют — контейнер можно не поднимать.

      Он самый прожорливый в стеке. Внутри полноценный Chromium: 200–350 МБ в покое и до 700 МБ плюс целое ядро на несколько секунд, когда решает проверку. На двухъядерном R1600 это заметно. Если он не нужен — закомментируйте сервис в media/compose.yaml; если нужен изредка — оставьте, но знайте, кого искать в списке «больше всех памяти» на дашборде Home Assistant.
    Раздел 4

    Prowlarr

    Единый список трекеров для всего стека: 192.168.3.53:9696. Индексаторы добавляются здесь один раз и автоматически появляются в Radarr — руками их там заводить не нужно и вредно.

    1. 4.1 Включить аутентификацию

      При первом открытии Prowlarr сам попросит завести учётную запись: метод Forms (Login page), имя и пароль. Начиная с первой версии обойти этот экран нельзя, и правильно.

      Заодно запомните, где лежит ключ API — он понадобится дальше: Settings → General → Security → API Key.

    2. 4.2 Добавить индексаторы

      Indexers → Add Indexer, найти трекер по названию. Для приватных понадобятся учётные данные или passkey из профиля на сайте трекера.

      После добавления нажмите Test у каждого. Зелёная галка — Prowlarr смог выполнить поиск от вашего имени.

      Красный крест с упоминанием Cloudflare или «challenge» — этому индексатору нужен FlareSolverr. Не удаляйте его, переходите к следующему шагу.

    3. 4.3 Привязать FlareSolverr

      Settings → Indexers → Indexer Proxies → «+» → выбрать FlareSolverr:

      Nameflaresolverr
      Tagsflaresolverr — создать новый тег
      Hosthttp://flaresolverr:8191

      Затем откройте каждый индексатор, которому нужен обход, и добавьте ему тот же тег flaresolverr в поле Tags. Прокси применяется только к отмеченным тегом — остальные ходят напрямую и не тратят время на запуск браузера.

      Почему адрес по имени контейнера. Prowlarr и FlareSolverr стоят в одной сети Docker media, где встроенный DNS разрешает имена сервисов. Адрес 127.0.0.1:8191 здесь не сработает: внутри контейнера Prowlarr это он сам.

    4. 4.4 Связать с Radarr

      Понадобится ключ API из Radarr: откройте 192.168.3.53:7878 → Settings → General → API Key и скопируйте.

      В Prowlarr: Settings → Apps → «+» → Radarr:

      Sync LevelFull Sync
      Prowlarr Serverhttp://prowlarr:9696
      Radarr Serverhttp://radarr:7878
      API Keyключ из Radarr

      Нажать Test, затем Save.

      Full Sync означает, что Prowlarr не только добавит индексаторы в Radarr, но и будет поддерживать их в актуальном состоянии: изменили настройки трекера здесь — они доедут туда сами.

    5. 4.5 Убедиться, что индексаторы доехали

      В Radarr: Settings → Indexers — там должны появиться те же трекеры, что и в Prowlarr.

      Не редактируйте их в Radarr. При следующей синхронизации Prowlarr перезапишет изменения, и вы будете долго искать, почему настройка «не сохраняется». Все правки — только в Prowlarr.
    Раздел 5

    Radarr

    Дирижёр конвейера: 192.168.3.53:7878. Он решает, что качать, следит за качеством, забирает готовое у qBittorrent и раскладывает по библиотеке.

    1. 5.1 Аутентификация и корневая папка

      Завести учётную запись при первом входе, метод Forms.

      Settings → Media Management → Root Folders → Add Root Folder: 

      /data/media/movies
      Путь пишется так, как его видит контейнер. Не /volume1/data/media/movies — внутри Radarr такого пути не существует. Если поле не принимает значение или показывает ошибку доступа, проверьте владельца папки: 1026:100.

    2. 5.2 Включить хардлинкиради этого всё

      Settings → Media Management, переключить наверху Show Advanced (иначе параметра не видно):

      ПараметрЗначение
      Use Hardlinks instead of Copyвключить
      Import Extra Filesвключить, srt, sub, ass
      Unmonitor Deleted Moviesвключить
      Rename Moviesвключить
      Replace Illegal Charactersвключить

      Схема именования — что-то в этом духе:

      {Movie CleanTitle} ({Release Year}) {imdb-{ImdbId}} [{Quality Full}][{MediaInfo VideoCodec}]

      Идентификатор IMDb в имени папки — не украшение: по нему Jellyfin находит правильный фильм даже когда название переведено или в нём опечатка.

    3. 5.3 Профиль качества под ваш телевизорэкономия

      Settings → Profiles → Quality Profiles. Разумный набор для вашей связки — разрешить Bluray-720p, WEBDL-720p, WEBRip-720p, Bluray-1080p, WEBDL-1080p, WEBRip-1080p; всё, что выше 1080p, выключить.

      Ограничение размера: Settings → Quality, для 1080p поставить верхнюю границу порядка 15 ГБ на фильм.

      Почему не 4K. LG 32LK540B — это матрица 1366×768. Даже 1080p телевизор показывает с уменьшением, а 4K-файл на 60 ГБ отличается от 1080p на 8 ГБ ровно ничем — кроме занятого места и риска, что приставке не хватит сил на прямое воспроизведение. HDR на этой матрице тоже не отображается. Профиль до 1080p экономит диск в разы, ничего не теряя на экране.
      Про кодеки. RockTek GX1 на Realtek RTD1325 аппаратно тянет H.264, H.265 и AV1 — прямое воспроизведение будет почти всегда. Но если однажды соберётесь смотреть с телефона или из браузера, помните: транскодировать эти файлы NAS будет программно, на двух ядрах.

    4. 5.4 Подключить qBittorrent

      Settings → Download Clients → «+» → qBittorrent:

      Hostqbittorrent
      Port9080
      Username / Passwordте, что задали в шаге 2.1
      Categorymovies — ровно как в шаге 2.4
      Remove Completedвыключить

      Нажать Test — должна появиться зелёная галка.

      Порт именно 9080, а не 8080. В compose.yaml задано WEBUI_PORT=9080, и внутри сети Docker обращаться нужно к нему же — публикация портов на хосте здесь ни при чём.
      Remove Completed выключен намеренно. Пусть лимиты раздачи из шага 2.6 решают судьбу торрента. Если разрешить Radarr удалять завершённые, раздача оборвётся сразу после импорта — а места это, благодаря хардлинкам, всё равно не освободит.

    5. 5.5 Уведомления в Пачкусвой бот

      Схема такая: в чате Кинозал живут четыре бота — по одному на Radarr, Prowlarr, Jellyfin и Seerr. Home Assistant говорит отдельно, своим ботом в чате Мониторинг.

      Готовые Liquid-шаблоны лежат в репозитории, в каталоге pachca/. Для Radarr:

      • Пачка → Автоматизации → Интеграции → Чат-боты и Вебхуки → Создать, имя Radarr;
      • поле шаблона: движок Liquid, содержимое pachca/radarr.liquid целиком;
      • вкладка Входящий вебхук → скопировать URL;
      • добавить бота только в чат Кинозал.

      В Radarr: Settings → Connect → «+» → Webhook, этот URL, метод POST, события On Grab, On File Import, On File Upgrade, On Health Issue, On Manual Interaction Required. Кнопка Test пришлёт «Проверка связи из Radarr» — это и проверяет, что шаблон сохранён верно.

      Почему у каждого сервиса свой бот. Шаблон задаётся на боте и применяется ко всем его сообщениям — не на вебхуке и не на чате. Одним ботом четыре разных payload не обслужить. И тем более нельзя вешать шаблон на бота Home Assistant: тот шлёт готовый текст {"message": "…"}, шаблон Radarr отрендерится в пустоту, и уведомления мониторинга молча прекратятся.
      Prowlarr настраивается так же — бот «Prowlarr», шаблон pachca/prowlarr.liquid, события On Health Issue и On Health Restored. Из всех уведомлений стека эти — самые ценные: молча отвалившийся индексатор выглядит как «Radarr вдруг перестал что-либо находить», и причину без подсказки ищут часами.

    6. 5.6 Добавить первый фильм

      Movies → Add New, найти что-нибудь заведомо доступное, выбрать корневую папку и профиль, включить Start search for missing movie, добавить.

      Дальше смотрите Activity → Queue: там появится торрент, и статус будет меняться от загрузки к импорту.

    Раздел 6

    Jellyfin

    Витрина библиотеки: 192.168.3.53:8096. Главная задача настройки — сделать так, чтобы он как можно реже транскодировал.

    1. 6.1 Пройти мастер и добавить библиотеку

      Язык, учётная запись администратора, затем Add Media Library:

      Content typeMovies
      Display nameФильмы
      Folder/data/media/movies
      Preferred metadata languageРусский
      CountryРоссия
      Библиотека смотрит только в media. В compose.yaml Jellyfin получает /volume1/data/media:/data/media:ro — доступ только на чтение и только к готовой библиотеке. Папку с загрузками он не видит вовсе, и это правильно: недокачанные файлы в библиотеке ни к чему.

    2. 6.2 Транскодирование: оставить выключеннымважно

      Панель → Воспроизведение → Транскодирование. Аппаратное ускорение — None, и это не оплошность:

      У AMD Ryzen R1600 нет встроенной графики. Аппаратного кодировщика в DS725+ физически нет — включать нечего. Любое транскодирование идёт программно на двух ядрах: один поток 1080p забирает их почти целиком, два уже рвутся. Если в списке ускорителей что-то выберется, работать это не начнёт, зато воспроизведение будет падать с ошибкой.

      Что стоит включить в том же разделе:

      Throttle Transcodesвключить — не даёт разогнать CPU в потолок
      Transcoding thread count2 — оставить ядро системе
      Allow subtitle extraction on the flyвыключить — частая скрытая причина нагрузки

    3. 6.3 Отключить лишнее

      • DLNA — если не пользуетесь, выключить: постоянные широковещательные рассылки в домашнем сегменте не нужны никому;
      • Панель → Расписания — сдвинуть сканирование библиотеки и генерацию превью на ночь;
      • Chapter image extraction — выключить, это самая тяжёлая фоновая задача на слабом процессоре.

    4. 6.4 Завести пользователя для приставки

      Панель → Пользователи → «+». Отдельная учётная запись удобнее общей административной: у неё своя история просмотра, на которой строится сценарий «Продолжить просмотр» в Home Assistant.

      Именно её идентификатор пойдёт в secrets.yaml как jellyfin_user_id.

    5. 6.5 Настроить клиент на приставке

      На RockTek GX1 установить Jellyfin из Google Play, адрес сервера — http://192.168.3.53:8096, вход под пользователем из шага 6.4.

      В настройках клиента выставить максимальное качество Auto / Direct play.

      Как проверить, что транскода нет. Запустите фильм и откройте Панель → Активность в Jellyfin. Строка Direct playing — файл отдаётся как есть, процессор свободен. Строка Transcoding с указанием кодеков — NAS пережимает видео на лету, и это надо расследовать: обычно виноват либо звук DTS, либо формат субтитров.

    Seerr

    Витрина запросов: 192.168.3.53:5055. Ставится последним, потому что связывается со всем остальным.

    1. 7.1 Подключить Jellyfin

      В мастере выбрать Jellyfin, адрес сервера: 

      http://jellyfin:8096

      Войти учётной записью администратора Jellyfin, затем на следующем шаге отметить библиотеку «Фильмы» и запустить сканирование.

    2. 7.2 Подключить Radarr

      Settings → Services → Add Radarr Server:

      Default Serverвключить
      Hostnameradarr
      Port7878
      API Keyиз Radarr → Settings → General
      Quality Profileтот, что собрали в шаге 5.3
      Root Folder/data/media/movies
      Minimum AvailabilityReleased

      Нажать Test, затем сохранить.

      Minimum Availability = Released — иначе Radarr начнёт искать фильм, которого ещё нет в природе, и будет дёргать индексаторы месяцами.

    3. 7.3 Пользователи и права

      Settings → Users → Import Users from Jellyfin. Для домашних можно включить Auto-Approve — тогда запрос уходит в Radarr сразу, без вашего подтверждения.

      Квоты стоит выставить даже дома. Settings → Users → General → Global Movie Request Limit, например 5 фильмов в неделю. Двухбайтовый NAS с двумя дисками заполняется быстрее, чем кажется, а гость с безлимитом и списком «топ-250» способен занять терабайт за вечер.

    4. 7.4 Уведомления в Пачку

      Заведите бота Seerr в чате Кинозал, шаблон — pachca/seerr.liquid. Затем в Seerr: Settings → Notifications → Webhook.

      Webhook URLвебхук бота Seerr
      JSON Payloadсодержимое pachca/payloads/seerr.json
      СобытияRequest Pending, Request Automatically Approved, Media Available, Request Failed
      У Seerr payload задаёте вы сами — в отличие от Radarr, где JSON фиксирован. Поэтому здесь два файла, которые правятся вместе: payloads/seerr.json определяет, что Seerr отправит, а seerr.liquid — как Пачка это покажет. Если поменяете поле в одном, поменяйте и во втором.
      Самое важное событие — Request Failed. Остальные приятны, но не срочны. Это означает, что запрос завис и без вас не поедет: обычно нет раздач или кончилось место на томе.

      Jellyfin настраивается похоже, но требует плагина Webhook: подробности и точные поля — в справочнике по Пачке.

    Сквозная проверка

    Один запрос, прошедший всю цепочку, проверяет больше, чем десять отдельных кнопок «Test».

    1. 8.1 Запросить фильм и проследить путь

      В Seerr найти фильм и нажать Request. Дальше смотреть по порядку:

      Где смотретьЧто должно произойти

      Radarr → Moviesфильм появился, отмечен как отслеживаемый
      Radarr → Activity → Queueидёт загрузка, виден индексатор и релиз
      qBittorrentторрент с категорией movies

      Если застряло — смотрите логи того звена, на котором остановилось:

      sudo docker logs -f --tail 80 radarr
sudo docker logs -f --tail 80 prowlarr
sudo docker logs -f --tail 80 qbittorrent

    2. 8.2 Проверить, что импорт прошёл хардлинкомглавная проверка

      Найдите файл в обеих папках и сравните номера inode: 

      sudo find /volume1/data -name '*.mkv' -newermt '-1 hour' -printf '%i\t%n\t%p\n' | sort -n

      Первая колонка — inode, вторая — число ссылок, третья — путь. Один и тот же inode на двух строках и цифра 2 во второй колонке — хардлинк создан, всё работает как задумано.

      Разные inode и по единице в колонке ссылок означают, что Radarr скопировал файл. Проверьте: включён ли Use Hardlinks instead of Copy (шаг 5.2), и смонтирован ли в обоих контейнерах один том /volume1/data:/data, а не две отдельные папки (шаг 1.2). До исправления каждый фильм будет занимать двойное место.
      # Сколько реально занято — с учётом того, что хардлинки считаются один раз
sudo du -sh --count-links=no /volume1/data/torrents /volume1/data/media 2>/dev/null || sudo du -sh /volume1/data
df -h /volume1
    Раздел 9

    Обслуживание

    1. 9.1 Включить встроенные бэкапы

      У Radarr и Prowlarr есть свои: Settings → General → Backups, интервал 7 дней, хранить 10. Они складываются в /config/Backups внутри контейнера, то есть в /volume1/docker/hh-homelab/media/config/<сервис>/Backups на NAS.

      Убедитесь, что /volume1/docker/hh-homelab входит в задание Hyper Backup — там же лежит и конфигурация Home Assistant.

    2. 9.2 Порядок обновления

      cd /volume1/docker/hh-homelab/media
sudo docker compose pull
sudo docker compose up -d
sudo docker image prune -f
      Обновляйте медиа-стек и Home Assistant порознь и не в один день. Если после обновления что-то сломается, вы будете точно знать, что именно, — а не гадать между шестью приложениями и полусотней интеграций.

    3. 9.3 Следить за местом

      Home Assistant уже присылает в Пачку предупреждение при 85 % и тревогу при 93 % заполнения тома. Когда придёт первое — самое время пройтись по завершённым раздачам.

      Освобождает место только удаление обеих ссылок: и торрента с файлами в qBittorrent, и фильма в Radarr. Удаление чего-то одного не даст ничего — данные останутся по второй ссылке.

    4. 9.4 Раз в квартал заглядывать в Prowlarr

      Indexers — проверить, что все зелёные. Трекеры меняют домены, закрываются и вводят новую защиту; молча переставший работать индексатор выглядит как «Radarr ничего не находит».
