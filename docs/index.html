    Что получится

    Home Assistant становится седьмым контейнером на DS725+ и работает в сети хоста — это единственный режим, в котором он видит телевизор по SSDP и умеет будить его magic-пакетом. Всё остальное вырастает вокруг него.

    Алиса. Официальной интеграции Home Assistant с Умным домом Яндекса не существует — ни у Nabu Casa, ни у Яндекса. Рабочий путь один: компонент yandex_smart_home, тоже из HACS.

    Раздел 1

    Подготовка DSM

    Пятнадцать минут в интерфейсе NAS и один git clone. Дальше вся конфигурация уже лежит на месте.

    1. 1.1 Включить SSH на NAS

      Панель управления → Терминал и SNMP → Терминал, поставить галку «Включить службу SSH». Порт оставьте 22.

      Зачем. Container Manager умеет собирать проект из готового compose.yaml, но склонировать репозиторий и выставить права через него нельзя. Три команды в терминале сэкономят полчаса кликов.

    2. 1.2 Склонировать репозиторийсуть

      Конфигурация не копируется в отдельную папку — клон и есть рабочая конфигурация. Подключитесь по SSH под своей учётной записью: 

      cd /volume1/docker
sudo git clone https://github.com/hhypest/hh-homelab.git
cd hh-homelab

# 1026:100 — тот же PUID:PGID, что и у остальных ваших контейнеров.
# Home Assistant внутри работает от root и всё равно сможет писать,
# а вы сможете править файлы через File Station.
sudo chown -R 1026:100 .
sudo chmod -R 755 homeassistant
      Почему именно клон, а не копия файлов. В compose.yaml каталог примонтирован относительным путём ./config, и Compose разрешает такие пути от каталога самого compose-файла. Рабочее дерево git — это и есть то, что читает Home Assistant: правка видна в git status сразу, обновление приходит одним git pull, а откат — обычным git checkout. Скопируете файлы в отдельную папку — потеряете всё это, и через месяц никто не скажет, какая версия свежее.

    3. 1.3 Проверить, что порты свободны

      sudo netstat -tulpn | grep -E ':(8123|2375)\s'

      Пустой вывод — всё хорошо. Ваш текущий стек занимает 9080, 6881, 9696, 7878, 8191, 8096, 7359 и 5055; DSM — 5000 и 5001. Пересечений нет.

    4. 1.4 Завести служебного пользователя hass

      Панель управления → Пользователь и группа → Создать. Имя hass, сложный пароль. Дальше по шагам мастера:

      • группа administrators — обязательно;
      • доступ к общим папкам — запретить все;
      • приложения — запретить все, оставив только DSM;
      • квота — не задавать.
      Зачем именно администратор. API DSM устроен так, что метрики системы (core.system, storage, SMART) отдаются только администраторам. Запрет на папки и приложения превращает такого администратора в аккаунт, который умеет ровно одно: отвечать на запросы статистики.
      Двухфакторная аутентификация. Если в DSM включено обязательное 2FA для administrators, для hass его нужно либо отключить индивидуально, либо приготовить OTP-код: интеграция спросит его один раз при подключении.

    5. 1.5 Внести NAS в белый список автоблокировки

      Панель управления → Безопасность → Автоматическая блокировка → Список разрешённых, добавить 192.168.3.53 и 127.0.0.1.

      Зачем. Home Assistant опрашивает DSM каждые несколько минут. Если однажды пароль в интеграции разойдётся с реальным, DSM забанит собственный адрес — и вместе с ним отвалятся Hyper Backup, DS file и всё остальное, что ходит через localhost.

    3. 2.3 Собрать проект в Container Manager

      Container Manager → Проект → Создать:

      • название проекта: homeassistant;
      • путь: /volume1/docker/hh-homelab/homeassistant;
      • источник: «Создать docker-compose.yml» → появится вопрос об уже существующем файле → выбрать использовать существующий;
      • веб-портал не настраивать → Готово.

      Эквивалент из терминала, если так привычнее:

      cd /volume1/docker/hh-homelab/homeassistant
sudo docker compose up -d

    4. 2.4 Дождаться первого старта

      Первый запуск занимает 2–5 минут: контейнер разворачивает базу и ставит зависимости.

      sudo docker ps --format 'table {{.Names}}\t{{.Status}}' | grep -E 'homeassistant|dockerproxy'
sudo docker logs -f --tail 50 homeassistant

      Готовность — строка Home Assistant initialized in …. После неё откройте http://192.168.3.53:8123.

      Если интерфейс не открывается. Проверьте, что контейнер действительно в host-сети: sudo docker inspect homeassistant --format '{{.HostConfig.NetworkMode}}' — должно вернуть host. Если вернулось default, значит проект собрался не из вашего compose.yaml.

    5. 2.5 Проверить docker-socket-proxy

      curl -s http://127.0.0.1:2375/version | head -c 200; echo
# Должен вернуться JSON с версией Docker.

# А снаружи NAS порт закрыт — проверьте с ноутбука (192.168.3.50):
curl -m 3 http://192.168.3.53:2375/version
# Ожидаемый результат: Connection refused.

      Подробнее о том, зачем нужен прокси, — в шаге 4.2.

    Раздел 3

    Первый вход и базовая настройка

    1. 3.1 Создать владельца

      Имя, логин, длинный пароль. Название дома — Home, чтобы совпадало с именем вашей Wi-Fi сети и не путаться потом. Местоположение можно указать мышкой на карте, координаты подставятся в профиль.

      На экране «Найденные устройства» Home Assistant, скорее всего, сразу предложит LG-телевизор и, возможно, Jellyfin. Пока ничего не подключайте — сделаем это осознанно в разделах 4 и 6.

    2. 3.2 Проверить конфигурацию

      Инструменты разработчика → YAML → Проверка конфигурации. Ожидаемый ответ — «Конфигурация действительна».

      Если конфигурация не прошла проверку, HA всё равно работает — просто не подхватил пакеты. Ошибка всегда указывает файл и строку; чаще всего это отступ или потерянные кавычки после ручного редактирования. Смотрите также Настройки → Система → Журналы.

    3. 3.3 Убедиться, что пакеты загрузились

      Инструменты разработчика → Состояния, фильтр binary_sensor.svc_. Должно быть шесть проверок, все в состоянии on.

      Что это. Каждая проверка — это HTTP-запрос к сервису на 127.0.0.1 раз в минуту. Контейнер может быть «запущен», а приложение внутри — висеть; такое ловится только реальным запросом. Скрипт bin/http_check.py считает успехом и коды 401/403: qBittorrent отвечает формой логина, и это нормальный признак жизни.

    4. 3.4 Установить HACSнужен дважды

      HACS — каталог сторонних компонентов. Он понадобится в двух местах: для Monitor Docker (метрики по каждому контейнеру, раздел 4) и для Yandex Smart Home (Алиса, раздел 8). Ставим сразу, чтобы не возвращаться. 

      sudo docker exec -it homeassistant bash -c "wget -O - https://get.hacs.xyz | bash -"
sudo docker restart homeassistant

      После перезапуска: Настройки → Устройства и службы → Добавить интеграцию → HACS. Мастер попросит открыть github.com/login/device и ввести код — HACS ходит в GitHub за репозиториями от вашего имени.

      Если код не принимается или страница не открывается — весь трафик NAS идёт через WireGuard, и GitHub может отвечать иначе, чем вы привыкли. Диагностика — раздел 9.1.

    5. 3.5 Поставить мобильное приложениепо желанию

      Home Assistant в App Store / Google Play, вход по адресу http://192.168.3.53:8123. Пока работает только из домашней сети; внешний доступ — раздел 9.

    Раздел 4

    Метрики NAS и контейнеров

    Четыре независимых источника. Они намеренно пересекаются: там, где это что-то даёт, — но ни один не дублирует другой ради красивой цифры.

    1. 4.1 Подключить Synology DSMоснова

      Настройки → Устройства и службы → Добавить интеграцию → Synology DSM:

      • хост: 192.168.3.53, порт: 5001;
      • SSL — включить, «Проверять сертификат» — выключить (у DSM самоподписанный сертификат);
      • пользователь hass и его пароль; при запросе — код OTP.

      На следующем экране выберите тома и диски для мониторинга — берите все.

      Появятся около сорока сущностей: загрузка CPU по составляющим, память, температура NAS и каждого диска, статус SMART, оставшийся ресурс дисков, занятое место на томах, скорость сети, аптайм, статус безопасности, а также кнопки перезагрузки и выключения.

      Обязательный шаг после подключения. Имена сущностей Synology строятся из имени NAS в DSM, а оно у вас может отличаться от ds725. Откройте Инструменты разработчика → Состояния, отфильтруйте по temperature, volume, cpu и подставьте реальные entity_id в packages/monitoring.yaml — там они помечены комментариями в автоматизациях 3.3–3.6, и в script.pachca_report.

    2. 4.2 Поднять docker-socket-proxyбезопасность

      Контейнер dockerproxy уже описан в compose.yaml и проверен на шаге 2.5. Здесь — про то, зачем он вообще нужен, потому что соблазн отдать сокет напрямую велик, а цена ошибки высока.

      Если проверка на шаге 2.5 показала, что порт отвечает снаружи NAS — вернитесь к секции ports в compose.yaml: адрес должен быть прибит к 127.0.0.1, и контейнер не должен стоять в host-сети.

      Почему не отдать сокет напрямую в Home Assistant. Доступ к /var/run/docker.sock равносилен root на NAS: имея его, можно запустить привилегированный контейнер и смонтировать любой том. Флаг :ro здесь не защищает — сокет не файл, права на чтение не мешают слать в него POST-запросы. Поэтому с сокетом говорит один маленький прокси, а он пропускает только те методы, которые перечислены в переменных окружения. По умолчанию стоит POST=0 — режим «только чтение».

    3. 4.3 Установить Monitor Dockerметрики контейнеров

      HACS → Интеграции → «⋮» → Пользовательские репозитории, добавить ualex73/monitor_docker с категорией Integration. Затем найти «Monitor Docker» в списке, скачать и перезапустить Home Assistant.

      Настройка уже лежит в packages/docker.yaml — компонент конфигурируется через YAML, а не через интерфейс. После перезапуска в Инструментах разработчика → Состояния отфильтруйте по sensor.docker_: должно быть около полусотни сущностей.

      СенсорЧто показывает
      sensor.docker_jellyfin_cpuзагрузка CPU этим контейнером, % (100 % = одно ядро)
      sensor.docker_jellyfin_memoryзанятая память, МБ
      sensor.docker_jellyfin_memory_percentageона же в процентах
      sensor.docker_jellyfin_staterunning / exited / paused
      sensor.docker_jellyfin_uptimeкогда контейнер стартовал
      sensor.docker_containers_runningсколько из восьми работает
      sensor.docker_top_cpuсамый прожорливый прямо сейчас, с именем в атрибуте

      sensor.docker_downраз в минутусколько контейнеров лежит; в атрибутах — имена, причина остановки и признак нехватки памяти
      Сверьте суффиксы один раз. Точные окончания _cpu, _memory, _memory_percentage зависят от версии компонента. Сводные sensor.docker_top_cpu и sensor.docker_top_ram ищут сущности по маскам _cpu$ и _memory$ — если в вашей версии окончания другие, поправьте маски в packages/docker.yaml, и всё остальное подхватится само.
      # Проверить быстрый сенсор состояния прямо в контейнере HA:
sudo docker exec homeassistant python3 /config/bin/docker_state.py
# Ожидается строка JSON: {"down": 0, "running": 8, "total": 8, ...}
      Метрики снимаются раз в час. В конфиге стоит scan_interval: 3600. Статистика Docker — самая дорогая часть опроса: демон открывает поток на каждый контейнер. Час вместо десяти секунд убирает постоянную нагрузку с двухъядерного R1600 и уменьшает поток записей в базу истории примерно в триста раз.

      Обратная сторона: у графиков CPU и памяти теперь 24 точки в сутки. Это отвечает на вопрос «сколько контейнер ест обычно», но не на «что было в 21:47». Нужна детализация — поставьте scan_interval: 300.

      Падения при этом ловятся за минуту, а не за час. Состояние контейнеров проверяет отдельный лёгкий скрипт bin/docker_state.py: один запрос GET /containers/json к прокси, без всякой статистики. Он создаёт сенсор sensor.docker_down с опросом раз в минуту, и именно на нём висит уведомление о падении. Метрики и надзор намеренно разведены по темпу — иначе пришлось бы выбирать между нагрузкой и скоростью реакции.

    4. 4.4 Свериться с HTTP-проверками

      Сравните sensor.docker_containers_running (должно быть 8) с шестью binary_sensor.svc_*. Расхождение — как раз тот случай, ради которого держим оба слоя: контейнер запущен, приложение внутри висит.

      Если какая-то из проверок в off, а сервис заведомо работает, подберите путь вручную:

      sudo docker exec homeassistant python3 /config/bin/http_check.py http://127.0.0.1:9696/ping 200
# ON — путь верный, OFF — попробуйте корневой /

    Раздел 5

    Уведомления в Пачку

    Входящий вебхук: Пачка выдаёт боту постоянный URL, любой POST с телом {"message": "…"} публикуется от его имени. Токен зашит в сам адрес — поэтому он живёт в secrets.yaml и больше нигде.

    1. 5.1 Создать чат «Мониторинг»

      В Пачке заведите групповой чат Мониторинг — сюда будет писать Home Assistant: железо, контейнеры, сервисы и утренняя сводка.

      Медиа-стек говорит отдельно, в чате Кинозал: там четыре своих бота — Radarr, Prowlarr, Jellyfin и Seerr. Их настройка — в чек-листе по медиа-стеку, шаги 6.5 и 8.4.

      Разделение по чатам — не эстетика. Входящий вебхук публикует сообщение во все групповые чаты, где состоит бот. Один бот в двух чатах — и сообщения дублируются в оба; бот Home Assistant в Кинозале — и туда полетят ночные сообщения о температуре диска.
      Почему именно так. В Мониторинге лежит то, что надо чинить, в Кинозале — то, что можно смотреть. Разные адресаты, разная срочность и разное время суток: сводку о дисках читают утром, «фильм скачался» — вечером.

    2. 5.2 Создать бота и получить URL

      • Автоматизации → Интеграции → Чат-боты и Вебхуки → Создать;
      • имя Home Assistant, аватар по вкусу;
      • поле шаблона оставить пустым — см. предупреждение ниже;
      • вкладка Входящий вебхук → скопировать URL целиком;
      • добавить бота участником только в чат Мониторинг.
      Шаблона у этого бота быть не должно. Home Assistant отправляет уже готовый текст — {"message": "…"}, — и Пачка публикует его как есть. Любой Liquid-шаблон на этом боте отрендерится в пустоту: полей movie или subject в нашем payload нет, а пустое сообщение Пачка не отправляет вовсе. Уведомления просто перестанут приходить, без единой ошибки в журнале.
      Шаблоны нужны ботам медиа-стека, и там всё наоборот: Radarr и Prowlarr шлют фиксированный JSON, который без шаблона выглядит как машинный мусор. Шаблон задаётся на боте и действует на все его сообщения — поэтому у каждого сервиса свой бот, а не один общий.

    3. 5.3 Вписать URL и перезагрузить конфигурацию

      # /volume1/docker/hh-homelab/homeassistant/config/secrets.yaml
pachca_webhook_url: "https://api.pachca.com/webhooks/ВАШ_ТОКЕН"

      Затем Инструменты разработчика → YAML → Перезагрузить всю YAML-конфигурацию.

    4. 5.4 Отправить тестовое сообщение

      Инструменты разработчика → Действия, выбрать script.pachca_notify, режим YAML: 

      action: script.pachca_notify
data:
  title: Проверка связи
  text: Если вы это читаете — вебхук работает.

      Ничего не пришло? Смотрите Настройки → Система → Журналы, строку rest_command. Код 404 — опечатка в URL; таймаут — исходящий трафик NAS уходит в WireGuard и не доходит до Пачки, см. раздел 9.

    Раздел 6

    Телевизор LG 32LK540BPLA

    Модель 2018 года на webOS 4.0 — интеграция LG webOS Smart TV её поддерживает полностью. Единственная тонкость — включение: выключенный телевизор по сети не слышно, нужен magic-пакет.

    1. 6.1 Подготовить телевизор

      Пультом, в меню Настройки → Все настройки:

      • Сеть → LG Connect Apps → Вкл — это разрешает управление по локальной сети;
      • Сеть → Мобильное включение ТВ (в некоторых прошивках «Включение по Wi-Fi») → Вкл;
      • Общие → Быстрый запуск+ → Вкл — без него телевизор в выключенном состоянии полностью обесточивает сетевой модуль и magic-пакет некому принять.
      Проводное подключение надёжнее. У серии LK Wake-on-LAN по Wi-Fi срабатывает через раз. Если есть возможность воткнуть кабель в один из портов Keenetic (все три в Vlan 1, домашний сегмент) — сделайте это, разница заметная.

    2. 6.2 Добавить интеграцию

      Включите телевизор. Home Assistant, скорее всего, уже нашёл его сам через SSDP — загляните в Настройки → Устройства и службы, раздел «Обнаружено». Если нет: Добавить интеграцию → LG webOS Smart TV, хост 192.168.3.52.

      На экране телевизора появится запрос на сопряжение — примите его пультом. Ключ доступа сохранится, повторно спрашивать не будет.

      Почему обнаружение вообще работает. SSDP — это широковещательные пакеты внутри одного сегмента. Home Assistant запущен в сети хоста, поэтому он в том же самом broadcast-домене, что и телевизор. В обычном bridge-контейнере обнаружения бы не было.

    3. 6.3 Привести entity_id к media_player.lg_tv

      Откройте сущность телевизора → шестерёнка → проверьте поле «Идентификатор сущности». Пакет media_tv.yaml ссылается именно на media_player.lg_tv; если HA назвал его иначе — переименуйте здесь либо поправьте ссылки в пакете.

    4. 6.4 Проверить включение

      Выключите телевизор пультом, подождите полминуты и вызовите media_player.turn_on для media_player.lg_tv из «Инструментов разработчика».

      Сработать должна автоматизация «ТВ: включение LG по Wake-on-LAN»: она отправляет magic-пакет на широковещательный адрес 192.168.3.255, а через две секунды — повторно. Двойная отправка не перестраховка: первый пакет телевизоры LK регулярно просыпают.

      Не включается. Проверьте по порядку: «Быстрый запуск+» включён; телевизор подключён кабелем; MAC в secrets.yaml совпадает с AA:BB:CC:DD:EE:FF из Keenetic; контейнер в host-сети (иначе пакет уходит в docker-мост и наружу не попадает).

    5. 6.5 Уточнить название HDMI-входа

      Откройте сущность телевизора в Инструментах разработчика → Состояния и посмотрите атрибут source_list. Найдите там разъём, в который воткнута приставка: у LG встречаются написания «HDMI 1», «HDMI1» и «HDMI-1».

      Если это не «HDMI 1», поправьте переменную tv_input в script.tv_on — в packages/media_tv.yaml она задана в одном месте.

      Это запасной путь, а не основной. При включённом SIMPLINK телевизор переключается на вход приставки сам, и переменная не понадобится. Она нужна для случаев, когда CEC не сработал — например, телевизор проснулся по Wake-on-LAN раньше, чем приставка успела подать команду.

      Сами сценарии просмотра — в разделе 7, после подключения приставки.

    6. 6.6 Уведомления на экранпо желанию

      Интеграция создаёт службу notify.lg_tv — всплывающее сообщение поверх картинки. Удобно для «фильм скачался» или «NAS перегревается», когда вы у экрана. Заготовка лежит в media_tv.yaml, закомментирована.

    Раздел 7

    Приставка и сценарии просмотра

    RockTek GX1 на Realtek RTD1325 — сертифицированная Google TV, поэтому подходит штатная интеграция Android TV Remote: тот же протокол, которым пользуется приложение Google TV на телефоне. Ни ADB, ни режим разработчика не нужны.

    1. 7.1 Закрепить адрес 192.168.3.54

      Приставка уже в домашнем сегменте. Зайдите в веб-интерфейс Keenetic, Мои сети и Wi-Fi → Список устройств, найдите её и нажмите «Зарегистрировать», закрепив 192.168.3.54.

      Зачем. Интеграция Android TV Remote хранит адрес, а не имя. Смена адреса после перезагрузки роутера разорвёт сопряжение, и все сценарии перестанут работать до повторной привязки.

    2. 7.2 Сопрячь с Home Assistant

      Добавить интеграцию → Android TV Remote, адрес 192.168.3.54. На экране телевизора появится шестизначный код — введите его в Home Assistant.

      Появятся две сущности: media_player (питание, громкость, что сейчас играет, запуск приложений) и remote (нажатия кнопок пульта и запуск приложений по ссылке или имени пакета).

    3. 7.3 Привести идентификаторы к ожидаемымважно

      Пакет media_tv.yaml ссылается ровно на три идентификатора. Проверьте их в карточках устройств и при необходимости переименуйте:

      Должно бытьУстройство

      media_player.rocktek_gx1приставка, 192.168.3.54
      remote.rocktek_gx1она же, пульт

    4. 7.4 Узнать реальное имя пакета Jellyfin

      Сценарий запускает приложение по имени пакета org.jellyfin.androidtv. Убедитесь, что у вас установлен именно официальный клиент: откройте Jellyfin на приставке пультом, а затем в Инструментах разработчика → Состояния посмотрите атрибут app_id у media_player.rocktek_gx1.

      Если там другое значение — подставьте его в script.tv_jellyfin в поле activity.

      YouTube запускается иначе — по ссылке https://www.youtube.com. Для приложений, у которых есть веб-адрес, это надёжнее имени пакета: Google TV сам сопоставляет ссылку с установленным приложением, и она не ломается при обновлении.

    5. 7.5 Настроить «Продолжить просмотр»

      Сценарий спрашивает у Jellyfin, на чём вы остановились, и отправляет это в сессию приставки. Нужны две записи в secrets.yaml.

      Первое — ключ API. В Jellyfin: Панель → Дополнительно → Ключи API → создать, назовите «Home Assistant».

      Второе — ваш ID пользователя:

      curl -s -H 'Authorization: MediaBrowser Token="ВАШ_КЛЮЧ"' \
  http://192.168.3.53:8096/Users | python3 -m json.tool | grep -E '"(Name|Id)"'

      Впишите обе строки:

      jellyfin_auth_header: 'MediaBrowser Token="ВАШ_КЛЮЧ"'
jellyfin_user_id: "a1b2c3d4e5f6..."

      Проверьте, что эндпоинт отвечает — на Jellyfin 10.10 и новее это /UserItems/Resume:

      curl -s -H 'Authorization: MediaBrowser Token="ВАШ_КЛЮЧ"' \
  'http://192.168.3.53:8096/UserItems/Resume?userId=ВАШ_ID&limit=1&mediaTypes=Video' \
  | python3 -m json.tool | head -20
      Если пришла ошибка 404, у вас Jellyfin старше 10.10. Тогда в packages/media_tv.yaml замените resource на http://127.0.0.1:8096/Users/ВАШ_ID/Items/Resume и уберите параметр userId из секции params.

      После перезагрузки YAML сенсор sensor.jellyfin_resume должен показывать название серии или фильма — например, «Северный ветер · S02E04».

    6. 7.6 Проверить сценарии по очереди

      Инструменты разработчика → Действия, запускать по одному с выключенным телевизором:

    7. 7.7 Проверить ночное автоотключение

      Настройки → Общие → SIMPLINK (HDMI-CEC) → Вкл. Именно на нём держится основной путь включения: приставка будит телевизор и переключает вход сама. Wake-on-LAN в сценарии — запасной вариант, и на серии LK по Wi-Fi он срабатывает через раз.

    Раздел 8

    Алиса

    Колонка стоит в изолированном сегменте — и это ничему не мешает. Голосовая команда уходит в облако Яндекса, оттуда навык Yaha Cloud стучится в Home Assistant по исходящему соединению самого NAS. Ни одного правила межсетевого экрана.

    1. 8.1 Убедиться, что HACS на месте

      HACS вы поставили на шаге 3.4 — он же принёс Monitor Docker в разделе 4. Проверьте, что интеграция жива: Настройки → Устройства и службы → HACS, ошибок быть не должно.

    2. 8.2 Поставить Yandex Smart Home

      HACS → Интеграции → Поиск «Yandex Smart Home» → Скачать → перезапустить Home Assistant.

      Если в каталоге не нашлось — добавьте репозиторий вручную: меню «⋮» → Пользовательские репозитории → dext0r/yandex_smart_home, категория Integration.

      Требование компонента — Home Assistant 2024.9 или новее. У вас свежая сборка, ограничение неактуально.

    3. 8.3 Настроить облачное подключение

      Добавить интеграцию → Yandex Smart Home → тип подключения «Облачное».

      Компонент выдаст пару ID и пароль — это учётные данные для привязки навыка. Сохраните их, они понадобятся на следующем шаге.

      Почему облачное, а не прямое. Прямое подключение требует, чтобы Яндекс мог достучаться до вашего Home Assistant по HTTPS из интернета — то есть публичный адрес, сертификат и открытый наружу порт. Облачный вариант переворачивает картину: Home Assistant сам держит исходящее соединение с Yaha Cloud. Наружу не открывается ничего.

    4. 8.4 Выбрать, что отдать Алисе

      В настройках интеграции — Список объектов. Разумный стартовый набор:

      • media_player.lg_tv — Алиса увидит его как телевизор: включение, выключение, громкость, каналы, источники;
      • media_player.rocktek_gx1 — приставка: пауза, громкость, что играет;
      • script.tv_on, script.tv_off, script.tv_jellyfin, script.tv_youtube, script.tv_jellyfin_resume — станут сценариями;
      • input_boolean.tv_no_auto_off — «Алиса, включи ночной просмотр», и автоматика не выключит телевизор посреди фильма;
      • температуру NAS и загрузку CPU — если хочется спрашивать голосом;
      • binary_sensor.stack_problem — одна лампочка вместо шести проверок.
      Не отдавайте всё подряд. Каждая сущность становится устройством в приложении «Дом с Алисой». Полсотни сенсоров превратят список в кашу, а распознавание команд — в лотерею.

    5. 8.5 Привязать навык в «Доме с Алисой»

      • приложение Дом с Алисой → Устройства → Добавить → Другое устройство;
      • найти навык Yaha Cloud (в некоторых версиях — «Yaha Cloud (YSH)»);
      • нажать «Привязать к Яндексу» и ввести ID и пароль из шага 8.3;
      • после привязки — Обновить список устройств.

      Устройства из Home Assistant появятся в приложении. Разложите их по комнатам и дайте человеческие имена.

      Имя решает всё. Алиса произносит и распознаёт ровно то имя, которое стоит в приложении Яндекса, а не в Home Assistant. «Телевизор» — хорошее имя. «media_player.lg_tv» — нет.

    6. 8.6 Проверить голосом

      ФразаЧто произойдёт

      Задержка 1–3 секунды — это нормально. Команда проходит путь «колонка → Яндекс → Yaha Cloud → ваш NAS» и обратно. Мгновенной реакции, как у локального управления, здесь не будет — это цена сохранённой изоляции сегментов.

    7. 8.7 Спросить у Алисы температурубез доп. компонентов

      Пакет packages/alice.yaml создаёт три псевдонима с предсказуемыми именами: sensor.server_temperature, sensor.server_cpu_load, sensor.server_ram_load. Подставьте в них свои сенсоры Synology — там три строки в самом начале файла.

      Отдайте Яндексу sensor.server_temperature и назовите устройство в приложении «Дом с Алисой» просто сервер. Работает сразу: 

      — Алиса, какая температура у сервера?
— Сорок один градус.
      Почему только температура. У Умного дома Яндекса закрытый список типов датчиков: температура, влажность, давление, заряд, освещённость, концентрации газов и ещё десяток. «Загруженности процессора» там нет и не появится — поэтому загрузка идёт другим путём, следующим шагом.

    8. 8.8 Научить Алису произносить отчёттретий компонент

      Чтобы услышать произвольную фразу с цифрами, колонка должна её сказать. Это умеет компонент YandexStation — в облачном режиме, то есть без локального доступа к колонке. Изоляция сегментов остаётся нетронутой.

      • HACS → Интеграции, найти «Yandex Station», скачать, перезапустить HA;
      • Добавить интеграцию → Yandex Station, вход по QR-коду — пароль компоненту не передаётся;
      • появится media_player для Мини 3.

      Скрипт script.alice_server_report сам найдёт колонку среди сущностей YandexStation — вписывать её идентификатор никуда не нужно. Проверьте его из Инструментов разработчика → Действия: колонка должна произнести что-то вроде «Процессор 11, память 47 процентов, 41 градусов. Всё работает».

      Затем отдайте этот скрипт Яндексу — он станет сценарием: 

      — Алиса, включи отчёт о сервере.
— Процессор одиннадцать, память сорок семь процентов,
  сорок один градусов. Всё работает.
      Сто символов — это потолок облачного режима. YandexStation обрезает всё, что длиннее. Фраза в sensor.server_voice_status собрана коротко и на всякий случай обрезается сама. Если захотите добавить в неё деталей — считайте символы, иначе Алиса замолчит на полуслове.
      Не хотите третий компонент? В самом низу packages/alice.yaml лежит закомментированный запасной вариант: отдать загрузку процессора как свойство «уровень заряда» устройству с именем «загрузка сервера». Тогда работает «Алиса, какой заряд у загрузки сервера» — цифру вы получите, но звучит это, прямо скажем, нелепо.
    Раздел 9

    Keenetic: что проверить

    Изоляцию сегментов не трогаем — она для новой схемы не помеха. А вот одну вещь из вашей конфигурации стоит проверить заранее, потому что она способна тихо сломать сразу три пункта чек-листа.

    1. 9.1 Понять, где сейчас ходит трафик NAS

      В вашей конфигурации политика Policy0 («Def») разрешает только Wireguard0 и явно запрещает ISP, и назначена она обоим сегментам и поимённо всем устройствам, включая NAS. То есть весь исходящий трафик NAS уходит в туннель «VPN».

      Это касается трёх вещей из этого чек-листа: Пачки (раздел 5), GitHub для HACS (раздел 8) и облака Yaha (раздел 8). Проверьте по SSH на NAS: 

      curl -s https://api.ipify.org; echo
curl -sS -o /dev/null -w 'pachca: %{http_code}\n' https://api.pachca.com/api/shared/v1/
curl -sS -o /dev/null -w 'yaha:   %{http_code}\n' https://yaha-cloud.ru/
curl -sS -o /dev/null -w 'github: %{http_code}\n' https://github.com/

      Любой код ответа лучше таймаута. Если всё отвечает — переходите к разделу 10, ничего менять не нужно.

    2. 9.2 Если что-то не отвечаетпо ситуации

      Три варианта, от точечного к радикальному:

      • Маршрут до узла. Интернет → Маршрутизация → Добавить маршрут: «Маршрут до узла», IP сервиса, интерфейс «Провайдер». Минус — у облаков адреса меняются.
      • Отдельная политика для NAS. Интернет → Приоритеты подключений → создать политику только с ISP → назначить её NAS. Учтите: Prowlarr и qBittorrent тоже выйдут из-под VPN.
      • Оставить как есть и слать уведомления другим каналом — например, в мобильное приложение Home Assistant.

    3. 9.3 Добавить резервный DNSрекомендую

      Сейчас единственный сервер имён — 10.0.0.53, и он объявлен только на интерфейсе Wireguard0. Пока туннель жив, всё хорошо; когда он упадёт, разрешение имён встанет во всей сети, включая Home Assistant. 

      # CLI роутера: ssh -p 2022 admin@192.168.3.1
ip name-server 77.88.8.8 "" on ISP
ip name-server 1.1.1.1 "" on ISP
system configuration save

      То же самое мышкой: Интернет → Проводной → Настройка DNS → Добавить сервер.

    4. 9.4 Опубликовать Home Assistant через KeenDNSпо желанию

      У вас уже настроен KeenDNS для DSM (ip http proxy nas). Добавим второе приложение: Управление → Доменное имя → Приложения → Добавить.

      • адрес сервера 192.168.3.53, порт 8123, протокол HTTP;
      • авторизацию роутера — выключить: у Home Assistant своя, а мобильное приложение не умеет проходить басик-авторизацию Keenetic.
      Секция http: уже готова к этому. В configuration.yaml прописаны use_x_forwarded_for: true и trusted_proxies: 192.168.3.1. Без них Home Assistant видел бы все запросы приходящими с адреса роутера и после пяти неудачных попыток входа заблокировал бы роутер целиком — вместе со всем внешним доступом.

      После настройки впишите адрес в secrets.yaml (ha_external_url) и раскомментируйте строку external_url в configuration.yaml.

    Раздел 11

    Бэкапы и обслуживание

    Скучный раздел, из-за которого потом не приходится собирать всё заново.

    1. 11.1 Включить встроенные резервные копии

      Настройки → Система → Резервные копии: расписание — ежедневно ночью, хранить последние 7. Копии складываются в /volume1/docker/hh-homelab/homeassistant/config/backups.

    2. 11.2 Добавить папку в Hyper Backup

      Включите /volume1/docker/hh-homelab/homeassistant в существующее задание Hyper Backup.

      Зачем и то, и другое. Встроенный бэкап Home Assistant восстанавливает конфигурацию и историю одним нажатием, но лежит на том же диске. Hyper Backup уносит копию наружу. Один без другого — половина защиты.

    3. 11.3 Порядок обновления

      cd /volume1/docker/hh-homelab/homeassistant
sudo docker compose pull
sudo docker compose up -d
sudo docker image prune -f
      Всегда сначала бэкап. Home Assistant обновляется раз в месяц и регулярно приносит breaking changes. Тег stable в compose.yaml означает «последний стабильный», а не «зафиксированный»: docker compose pull действительно поднимет версию. Если хотите контролировать момент — замените :stable на конкретную версию, например :2026.8.

    4. 11.4 Следить за размером базы

      ls -lh /volume1/docker/hh-homelab/homeassistant/config/home-assistant_v2.db

      В configuration.yaml заданы purge_keep_days: 21 и commit_interval: 15 — история за три недели, запись пачками раз в 15 секунд вместо постоянного потока мелких транзакций. Для NAS это заметная разница по износу дисков. Если база перевалит за пару гигабайт, добавьте в recorder.exclude самые говорливые сенсоры — обычно это скорости сети.
