    1.0.0

    Первый выпуск

    2 сентября 2026. Домашний сервер на Synology DS725+ собран, описан и закрыт проверками. Версия 1.0 фиксирует не только файлы конфигурации, но и то, что реально работает: все образы закреплены на конкретных тегах, так что клон этого тега поднимет ту же систему, а не «примерно такую же».

    Что это

    Два независимых compose-проекта на одном NAS. Медиа-стек — шесть контейнеров, превращающих запрос в Seerr в фильм в библиотеке Jellyfin без единого лишнего копирования по диску. Home Assistant — метрики NAS и контейнеров, уведомления в Пачку, управление телевизором и приставкой, голосовые сценарии через Алису.

    Клон репозитория и есть рабочая конфигурация: оба стека монтируют своё состояние относительными путями, поэтому весь сервер переносится вместе с репозиторием, а правки видны в git status сразу.

    Состав выпуска

    Версии получены сверкой дайджестов: для каждого образа взят дайджест плавающего тега и найден версионный тег, ведущий на тот же самый образ. То есть закреплено ровно то, что работало на момент выпуска.

    Что вошло

    Медиа-стек. Шесть контейнеров в общей bridge-сети. Импорт хардлинком вместо копирования: файл в библиотеке и раздающийся торрент — одни и те же данные, место занято один раз, раздача не прерывается. Профиль качества под конкретный телевизор, чтобы не тащить 4K на панель 1366×768.

    Home Assistant. Метрики NAS через интеграцию Synology DSM, метрики контейнеров — через docker-socket-proxy, который пропускает только чтение: сам сокет в HA не пробрасывается, потому что доступ к нему равносилен root на NAS. HTTP-проверки живости каждого сервиса, статистика простоя, уведомления в Пачку с разделением по чатам.

    Уведомления. Пять ботов, два чата: в одном то, что смотреть, в другом то, что чинить. Liquid-шаблоны на каждый сервис лежат в репозитории и проверяются локально на сохранённых примерах payload, а не «дождёмся настоящего события».

    Телевизор и приставка. Wake-on-LAN, сценарии просмотра, голосовое управление через Алису по облачному подключению. Отдельно разобрано, почему телевизор остаётся на кабеле: WoL по Wi-Fi требует WoWLAN, которого у этой модели нет.

    Конфигурация вынесена в .env. Репозиторий публичный, и всё, что относится к конкретной машине — права, часовой пояс, корень библиотеки, адрес привязки, имя сети и порты, — живёт в файле рядом с compose. Значений по умолчанию нет намеренно: забытый .env роняет запуск с внятным сообщением, а не поднимает стек с пустыми значениями.

    Восемь задач проверок в CI и 146 тестов. Проверяется не только синтаксис: список контейнеров под надзором сверяется с compose-файлами, каждый entity_id — с тем, кто его создаёт, переменные — с образцом .env.example, порты, по которым Home Assistant опрашивает сервисы, — с ним же, счётчики шагов в README — с самими страницами, а образы — с требованием иметь закреплённую версию. Каждая такая проверка появилась после случая, когда что-то разошлось молча.

    Выпуски делает workflow, а не человек в терминале. Тег, релиз и его описание собираются одной кнопкой, с отказом на невнятной версии, повторном теге, неописанной версии и любой упавшей проверке. Подробнее ниже, в разделе «Как выпускается версия».

    Восемь страниц документации с отметками о прогрессе: два чек-листа развёртывания, гайд по журналам, обзор проекта, справочник по уведомлениям, заметки по роутеру, дорожная карта и эта страница. Обезличивание проверяется автоматически — MAC-адреса, имена устройств и имя точки доступа в публичный репозиторий не попадают.

    Известные ограничения

    ЧтоПочему так
    Транскодирование только программноеу Ryzen R1600 нет встроенной графики, аппаратного кодировщика в DS725+ физически нет. Один поток 1080p забирает оба ядра почти целиком
    VueTorrent обновляется рукамимод подключён через DOCKER_MODS, а Dependabot разбирает в compose-файле только ключ image
    Нет проверки конфигурации настоящим Home Assistanthass --script check_config требует установленных компонентов HACS; текущие проверки разбирают YAML и шаблоны, но не знают, существует ли интеграция
    Падение самого NAS никто не заметитвсё, что шлёт уведомления, работает на нём же. Внешний пульс — третий пункт дорожной карты
    Замеры NAS не приведеныони зависят от дисков, сети и содержимого библиотеки. В обзоре вместо чисел дан протокол, по которому вы получите свои

    Как обновляться дальше

    Обновления образов приходят пул-реквестом от Dependabot раз в неделю, одной группой на оба стека. Порядок обратный привычному: docker compose pull сам версию больше не поднимает. 

    # 1. прочитать changelog, смержить PR от Dependabot
# 2. на NAS:
cd /volume1/docker/hh-homelab
git pull
cd media && sudo docker compose pull && sudo docker compose up -d

    Полный порядок с проверкой локальных правок — в чек-листе медиа-стека, шаги 10.2 и 10.3, и в чек-листе Home Assistant, шаги 11.3 и 11.4. Откат — обычный git revert: версии лежат в репозитории, а не в памяти.

    Как выпускается версия

    Actions → Выпуск → Run workflow, ввести номер вида 1.2.3. Дальше всё само: тег, релиз и его описание. Руками в терминале ничего делать не нужно.

    Прежде чем что-то создать, workflow отказывается работать, если:

    • номер не похож на X.Y.Z — v1.0.0 и 1.0 не пройдут;
    • такой тег уже есть — выпуск не перевыпускают;
    • на этой странице нет раздела с такой версией либо в шапке значится другая. То есть выпустить версию, которую забыли описать, нельзя;
    • не проходит хоть одна проверка репозитория. Они прогоняются заново, а не берутся на веру по прошлому зелёному прогону.
    Сначала вхолостую. У запуска есть галка «Только проверить»: все сверки пройдут, но ни тега, ни релиза не появится. Стоит нажать её первой, если выпускаете нечасто и не помните, что именно проверяется.
    Состав выпуска не пишется руками. Таблица версий собирается из самих compose.yaml в момент выпуска, поэтому описание релиза физически не может разойтись с тем, что закреплено в конфигурации. Ровно та же мысль, что и в остальных проверках: всё, что может тихо разойтись, сверяется машиной.

    Что осознанно не сделано

    Kubernetes, 4K-библиотека, аппаратное транскодирование и локальный доступ Алисы — с поводами и разбором в дорожной карте, раздел «Сознательно не делаем». Смысл не в том, чтобы закрыть тему, а в том, чтобы через полгода не проходить те же рассуждения заново.
