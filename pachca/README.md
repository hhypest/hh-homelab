# Уведомления медиа-стека в Пачку

Liquid-шаблоны, которые превращают JSON от Radarr, Prowlarr, Jellyfin
и Seerr в читаемые сообщения.

## Главное ограничение, из которого всё следует

**Шаблон задаётся на боте и применяется ко всем сообщениям этого бота.**
Не на вебхуке, не на чате — на боте.

Отсюда два следствия, о которые спотыкаются все:

1. Нельзя повесить шаблон Radarr на бота, через которого уже ходят
   уведомления Home Assistant. Тот шлёт `{"message": "готовый текст"}`,
   под шаблон Radarr это не подойдёт, и вместо сообщений вы получите
   пустоту.
2. Четыре сервиса с разными payload — это либо четыре бота с четырьмя
   шаблонами, либо один бот с одним шаблоном, который сам разбирается,
   кто прислал.

Здесь есть оба варианта.

## Вариант А: по боту на сервис — рекомендуется

Четыре бота: «Radarr», «Prowlarr», «Jellyfin», «Seerr». У каждого свой
аватар, и в чате сразу видно, кто говорит. Каждый шаблон короткий и
правится независимо.

| Бот | Шаблон | Payload задаёт |
|---|---|---|
| Radarr | [`radarr.liquid`](radarr.liquid) | сам Radarr, поменять нельзя |
| Prowlarr | [`prowlarr.liquid`](prowlarr.liquid) | сам Prowlarr, поменять нельзя |
| Jellyfin | [`jellyfin.liquid`](jellyfin.liquid) | вы — [`payloads/jellyfin.handlebars`](payloads/jellyfin.handlebars) |
| Seerr | [`seerr.liquid`](seerr.liquid) | вы — [`payloads/seerr.json`](payloads/seerr.json) |

## Вариант Б: один бот на всё

Один бот «Медиа», один шаблон [`media-router.liquid`](media-router.liquid).
Он определяет отправителя и разбирает payload сам.

Платите за это сокращённым набором событий: в маршрутизаторе разобрано
только то, ради чего уведомления и заводят, остальное сводится к одной
строке. Полные версии — в четырёх файлах выше.

Как он узнаёт отправителя: Jellyfin и Seerr формируют payload сами, и в
шаблонах из `payloads/` им прописано поле `service`. Radarr и Prowlarr
шлют фиксированный JSON, где есть `instanceName`; если и его нет,
Radarr опознаётся по наличию объекта `movie`.

## Настройка

### 1. Бот и вебхук

Пачка → **Автоматизации → Интеграции → Чат-боты и Вебхуки → Создать**.
Имя и аватар по сервису. Вкладка **Входящий вебхук** → скопировать URL.
Добавить бота в чат, где хотите видеть уведомления.

Там же, в настройках бота, — поле шаблона: движок **Liquid**, содержимое
соответствующего `.liquid` файла целиком.

> Заведите для этого отдельный чат. Входящий вебхук публикует сообщение
> во **все** групповые чаты, где состоит бот, — иначе в рабочий чат
> прилетит «Prowlarr: индексатор недоступен» в три часа ночи.

### 2. Radarr

**Settings → Connect → «+» → Webhook**

| Поле | Значение |
|---|---|
| URL | вебхук бота Radarr |
| Method | POST |
| События | On Grab, On File Import, On File Upgrade, On Movie Delete, On Health Issue, On Health Restored, On Manual Interaction Required |

Кнопка **Test** пришлёт «Проверка связи из Radarr» — это и есть проверка,
что шаблон сохранён верно.

### 3. Prowlarr

**Settings → Connect → «+» → Webhook**, события: **On Health Issue**,
**On Health Restored**, **On Application Update**.

Событие «On Release Grab» включайте, только если хотите видеть каждый
запрос от Radarr — это довольно шумно и дублирует «On Grab» из Radarr.

> Prowlarr — единственный, чьи уведомления стоит включить, даже если все
> остальные вы отключите. Молча отвалившийся индексатор выглядит как
> «Radarr вдруг перестал что-либо находить», и без этого сообщения
> причину ищут часами.

### 4. Jellyfin

Нужен плагин: **Панель → Плагины → Каталог → Webhook**, установить,
перезапустить Jellyfin.

**Панель → Плагины → Webhook → Add Generic Destination**:

| Поле | Значение |
|---|---|
| Webhook Name | Пачка |
| Webhook Url | вебхук бота Jellyfin |
| Notification Type | Item Added, Playback Start, Authentication Failure, User Locked Out |
| Item Type | Movies (и Episodes, если появятся сериалы) |
| Template | содержимое [`payloads/jellyfin.handlebars`](payloads/jellyfin.handlebars) |

Галку **Send All Properties** не ставьте: она игнорирует шаблон и шлёт
всё подряд, отчего Liquid-шаблон перестанет находить свои поля.

### 5. Seerr

**Settings → Notifications → Webhook**

| Поле | Значение |
|---|---|
| Webhook URL | вебхук бота Seerr |
| JSON Payload | содержимое [`payloads/seerr.json`](payloads/seerr.json) |
| Типы уведомлений | Request Pending, Request Automatically Approved, Media Available, Request Failed |

## Проверка без ожидания событий

Ждать настоящего события, чтобы узнать, что в шаблоне опечатка, — плохой
способ. Все шаблоны прогоняются локально на сохранённых примерах:

```bash
pip install python-liquid
python3 scripts/render_pachca.py            # показать все сообщения
python3 scripts/render_pachca.py radarr     # только Radarr
python3 scripts/render_pachca.py --check    # молча, для CI
```

Скрипт рендерит каждый шаблон на каждом подходящем примере из
[`samples/`](samples/) и заодно проверяет две вещи, которые Пачка не
простит: пустое сообщение и превышение лимита в 40 000 байт.

То же самое гоняется в CI на каждый push — сломанный шаблон не доедет
до main.

Добавляете новое событие — положите рядом пример
`samples/<сервис>-<событие>.json`, и он подхватится сам. Настоящий payload
удобно взять из логов: включите событие, нажмите Test и посмотрите, что
пришло.

## Что учтено в шаблонах

**Все обращения к полям защищены `default`.** Сервисы шлют разный набор
полей в разных событиях, и отсутствующее поле в Liquid рендерится в
пустоту — сообщение выходит рваным, но не падает. С `default` вместо
дырки будет прочерк.

**Размер считается в гигабайтах явно.** `release.size` приходит в байтах;
`divided_by: 1073741824.0` с точкой на конце — это не опечатка, а
принудительное деление с плавающей точкой: без неё Liquid поделит нацело
и любой фильм окажется «8 ГБ».

**Import и Upgrade — одно событие.** Radarr шлёт `eventType: "Download"`
и в том, и в другом случае; отличает их булев флаг `isUpgrade`. Шаблон
показывает разные иконки, чтобы обновление качества не путалось с новым
фильмом.

**Транскодирование отмечается отдельно.** В уведомлении Jellyfin о начале
воспроизведения строка `playMethod` показывается всегда, а `Transcode`
дополнительно помечается предупреждением: на DS725+ без аппаратного
кодировщика это означает, что оба ядра заняты пережатием видео.

**Кавычки в названиях.** Jellyfin и Seerr подставляют значения прямо в
JSON, который вы задали. Название фильма с двойной кавычкой сломало бы
разбор. У Jellyfin двойные фигурные скобки экранируют HTML, поэтому
кавычка приедет как `&quot;` — некрасиво, но JSON цел. У Seerr такой
защиты нет; за пять лет это ломалось у людей считанные разы, но если
однажды сообщение не придёт вовсе — смотрите в эту сторону.
