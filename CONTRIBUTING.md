# Как править этот репозиторий

Репозиторий — конфигурация одного домашнего сервера, а не библиотека
общего назначения. Поэтому правила короткие.

## На каких условиях принимаются правки

Присылая pull request, вы соглашаетесь, что ваша правка попадает в
репозиторий на тех же условиях, на которых лежит остальное содержимое:
код — под [MIT](LICENSE), текст — под
[CC BY 4.0](LICENSES/CC-BY-4.0.txt). Границу между тем и другим проводит
[`NOTICE.md`](NOTICE.md).

Это обычное правило «что входит, то и выходит»: отдельного соглашения
подписывать не нужно, авторские права остаются за вами, а репозиторий
получает право распространять вашу правку наравне со всем прочим.

Не присылайте чужой текст и чужой код, если не имеете права выпустить их
на этих условиях. Кусок из чужого руководства, перенесённый в страницу
целиком, — это как раз тот случай.

## Что проверяется до слияния

Восемь задач CI, все обязательные. Локально то же самое выполняется
меньше чем за пятнадцать секунд:

```
ruff check .                                  # Python · ruff и тесты
python -m pytest tests/                       #   (то же, вторая половина задачи)
yamllint homeassistant media pachca .github   # YAML · форматирование
python scripts/validate_config.py             # Конфигурация · YAML, Jinja, секреты
python scripts/validate_entities.py           # Конфигурация · ссылки на сущности
python scripts/render_pachca.py --check       # Пачка · Liquid-шаблоны
python scripts/validate_docs.py               # Документация
python scripts/check_files.py                 # Файлы · переводы строк и пробелы
```

Восьмая задача — `Docker Compose · оба стека` — единственная, которой
нужен установленный Docker. Она разворачивает оба файла на образцах
`.env.example`, то есть заодно проверяет и сами образцы: забыли
переменную в образце — упадёт здесь, а не у человека на NAS.

```
docker compose -f media/compose.yaml \
  --env-file media/.env.example config --quiet
docker compose -f homeassistant/compose.yaml \
  --env-file homeassistant/.env.example config --quiet
python scripts/check_ports.py media/compose.yaml homeassistant/compose.yaml
```

Если правите только документацию, эту часть можно пропустить. Если
трогаете `compose.yaml` или `.env.example` — нельзя: конфликт портов и
незаполненная переменная иначе обнаружатся только после push.

Ещё одна проверка в CI не участвует и запускается по желанию — она ходит
в реестр, а сети в проверках на каждый push быть не должно:

```
python3 scripts/check_image_updates.py
```

Она сверяет закреплённые в compose теги с тем, что лежит в реестре, включая
образ мода из `DOCKER_MODS`. Это единственный способ узнать, что образы
отстали: Dependabot по ним больше не следит — экосистема `docker-compose`
две недели молчала, пока шесть образов уходили вперёд, и её убрали.
Запускать перед тем, как поднимать версии, и раз в пару недель просто так.

Отдельно стоит знать про три проверки, которые ловят не синтаксис:

* **`validate_docs.py`** сверяет ссылки вида «шаг 5.3» с номерами шагов
  на целевой странице — и внутри HTML, и из Markdown. Переставили шаг —
  проверка укажет, где текст остался звать в старый номер.
* **`tests/test_docs_counters.py`** сверяет числа в шапках страниц с
  репозиторием: сколько тестов, сколько страниц, сколько файлов под
  версией. Добавили тест — число обновится не само, но и разъехаться
  молча не сможет.
* **`tests/test_license.py`** требует, чтобы каждый файл под версией попадал
  в какую-то категорию карты лицензий из `NOTICE.md`, а каждый образ
  из compose был там назван. Завели новый каталог или сервис — придётся
  сказать, на каких он условиях.

## Тест обязан уметь провалиться

Правка, которая что-то чинит, приходит с тестом, и этот тест **сначала
проверяется на коде до правки**: он должен там упасть. Тест, зелёный
в обоих случаях, ничего не держит — он только создаёт ощущение покрытия.

Повод у правила конкретный. Внешний разбор кода нашёл сразу несколько
проверок, которые не могли провалиться в принципе: список отслеживаемых
файлов собирался вызовом `git ls-files` и при любой ошибке возвращался
пустым, а проверка на этом честно сообщала, что обошла ноль файлов, и
завершалась успехом. Рендер шаблонов Пачки объявлял «проблем 0», даже
когда не отрисовал ни одного. Тест на сводку искал шаблон подстрокой
и продолжал проходить после того, как правка сломала соседний шаблон.

Отсюда же требование к самим проверкам: пустой результат — это отказ,
а не успех. Обошли ноль файлов, отрисовали ноль шаблонов, не нашли
ни одной строки для сверки — значит проверка сломана, и она обязана
сказать об этом, а не промолчать.

## Обезличивание

Репозиторий публичный, и в него нельзя возвращать личные данные:
MAC-адреса, имена устройств и Wi-Fi сетей, боевые вебхуки, ключи
Jellyfin, UUID клиентов VLESS, токены доступа. Это проверяется
`validate_docs.py` по всем файлам под версией, но проверка знает только
те формы записи, которые в неё заложены, — она страхует, а не заменяет
внимательность.

Для примеров заведены заглушки: `AA:BB:CC:…` для MAC, UUID из одних
нулей. Пользуйтесь ими, а не «почти настоящими» значениями.

## Оформление

* Одна правка — один коммит с осмысленным заголовком по-русски.
  Заголовок называет, **что** изменилось, а тело — **почему**.
* Файлы заканчиваются переводом строки, без CRLF и хвостовых пробелов.
  Это проверяет `check_files.py`.
* Числа и утверждения в документации должны быть проверяемыми. Если
  число нельзя получить командой, лучше не писать его вовсе, чем
  написать приблизительное: на него потом сошлются.
* Правки в `docs/` — это текст под CC BY. Пишите так, чтобы через
  полгода было понятно не только что нажимать, но и почему именно так.

## Что не нужно присылать

* Поддержку своего железа «на всякий случай». Реестр того, что зависит
  от конкретной машины, ведётся в
  [«Других платформах»](https://hhypest.github.io/hh-homelab/portability.html)
  — туда и стоит добавлять.
* Секреты, даже в примерах.
* Правку версии образа без объяснения, что она чинит: версии закреплены
  намеренно, поднимаются вручную и по одной причине за раз. Что именно
  отстало, показывает `scripts/check_image_updates.py`.
